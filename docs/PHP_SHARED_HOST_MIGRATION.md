# انتقال حضوریار به هاست اشتراکی خطیار — برنامه و وضعیت

## تصمیم معماری

مسیر فعال PHP خطیار در مرجع موجود `php/app/index.php` + `php/lib/Db.php` + MySQL/MariaDB از طریق PDO است؛ فایل `.htaccess` مسیر `/api` را به روتر PHP هدایت می‌کند. بخش Node موجود در مخزن خطیار نباید به‌عنوان مرجع قطعی اجرای هاست فرض شود. بنابراین **نسخه نهایی هاست اشتراکی حضوریار باید PHP 8.1+ و MySQL/MariaDB باشد** و سرویس دائمی Node یا SQLite را الزام نکند. این انتقال مستقل از پایگاه داده خطیار است.

## وضعیت فعلی این شاخه

- **مرحله ۱ — زیرساخت PHP (آماده برای آزمایش، نه انتشار):** `php/app/index.php`، `php/lib/Db.php`، `php/lib/Auth.php`، فایل آغازین InnoDB، نمونه پیکربندی خارج از DocumentRoot و اسکریپت CLI ساخت شرکت/مالک.
- **مرحله ۲ — زیرمجموعه پرسنل و تردد (پیاده‌سازی و آزمون محلی):** `php/db/002_personnel_attendance.sql` و ماژول‌های `PersonnelApi.php`، `ShiftApi.php`، `AttendanceApi.php`، شامل کاربران، مناطق، تنظیمات شرکت، شیفت‌ها، تخصیص و ورود/خروج GPS با قفل تراکنشی شرکت/کاربر، شناسه رویداد تکرارپذیر و ثبت ممیزی. سیاست پنجره شیفت با تابع `WorkCalc::allowedShiftTraffic()` منتقل و با رفتار نسخه Node تطبیق داده شد؛ نبود شیفت مجاز، خروج از پنجره ورود/خروج و روز غیرکاری رد می‌شود.
- **مرحله ۳ — درخواست‌های پرسنلی (پیاده‌سازی اولیه بدون آزمون PHP):** `php/db/003_requests.sql` و `php/lib/RequestsApi.php` شامل درخواست روزانه/ساعتی استحقاقی، استعلاجی، بدون حقوق و مأموریت، فهرست و تصمیم‌گیری ۱/۲ مرحله‌ای، بررسی سقف مرخصی در سال شمسی، فهرست جانشین‌ها و رزرو تراکنشی در شرکت. برای تبدیل قطعی سال شمسی از `IntlDateFormatter` استفاده می‌شود؛ بسته PHP `intl` باید نصب باشد. مرخصی و جانشینی هنوز در **موتور گزارش کارکرد PHP** مصرف نمی‌شوند و تا آن زمان گزارش عملیاتی PHP آماده نیست.
- **مرحله ۴ — تقویم (پیاده‌سازی اولیه بدون آزمون PHP):** `php/db/004_calendar.sql` و `CalendarApi.php`؛ دریافت برخط تعطیلات مستقل از خطیار با اعتبارسنجی پاسخ سرویس، کش یک‌ساعته MySQL و fallback به کش معتبر در قطعی، بدون ساختن تعطیل رسمی حدسی. تعطیلات دستی مستقل شرکت‌ها هستند. برای دریافت آنلاین `curl` لازم است.
- **مرحله ۵ — موقعیت، نظارت و درگاه‌ها (پیاده‌سازی اولیه بدون آزمون PHP):** `php/db/005_monitoring.sql` و `MonitoringApi.php`؛ ثبت موقعیت فقط در حضور فعال، تاریخچه ۳۰روزه، نمایش آخرین نقطه معتبر، شواهد صریح قطع GPS/اینترنت، پراکسی کاشی نشان و پیامک کاوه‌نگار با کلید هر شرکت. کنترل‌های سختگیرانه سروری، زمان انقضا و تفکیک دسترسی در کد قرار گرفته‌اند، اما ارسال واقعی با کلید معتبر و رفتار روی دستگاه هنوز آزمون نشده‌اند.
- **مرحله ۶ — داشبورد (پیاده‌سازی اولیه بدون آزمون PHP):** `DashboardApi.php`؛ شمار پرسنل فعال، افراد با حضور باز و ورودهای یکتا در بازه حداکثر ۳۵روزه، با فیلتر شرکت و تاریخ تهران. زمان تاریخی ایران در این گزارش به‌صورت `UTC+03:30` در SQL محاسبه شده است؛ داده‌های پیش از لغو تغییر ساعت رسمی، به آزمون تطبیقی نیاز دارند.
- **مرحله ۷ — محاسبه کارکرد (موتور و آزمون PHP):** `WorkCalc.php` و `WorkReportApi.php`؛ محاسبه حضور واقعی، شب‌کاری، شیفت ثابت/هفتگی/شناور/چرخشی/چندبازه‌ای، مرخصی و مأموریت، جانشینی تأییدشده و دقیقه‌های نظارتی غیرمالی. گزارش `authoritative:false` است. فایل `tests/php-work-parity.test.mjs` هشت سناریو را با موتور Node موجود مقایسه می‌کند؛ روی محیط دارای PHP اجرا و تمام هشت سناریو موفق شدند.
- **مرحله ۸ — بایگانی و امضای دقیقه‌ای مالی (آزمون PHP/MySQL):** `php/db/006_work_archives.sql` و `ArchiveApi.php`؛ snapshot ماه پایان‌یافته، جلوگیری از ثبت دوباره، توقف در حضور باز/درخواست معلق، بررسی مدیر میانی، تأیید مالک و امضای SHA-256 همراه پیش‌نمایش دقیقه‌های قابل پرداخت. این گواهی هنوز پرداخت ریالی یا محاسبه مالیات/بیمه نیست. سناریوی آزمایشی MariaDB شامل archive/retry/review/approve/preview/finance-confirm/integrity موفق شد.
- **مرحله ۹ — اکسل بایگانی (پیاده‌سازی و آزمون ساختار):** `XlsxExport.php` و `GET /api/work-months/{month}/xlsx`؛ خروجی OOXML مستقل از Node، راست‌به‌چپ با تیتر بنفش و قالب `[h]:mm`، تفکیک هر شرکت بر اساس نشست و خواندن snapshot ثابت. صحت اجزای ZIP و محتوای XML در آزمون PHP بررسی شد؛ سازگاری نمایشی در نسخه‌های Excel/LibreOffice واقعی باید جداگانه آزموده شود.
- APIهای احراز هویت: `GET /api/health`، `POST /api/login`، `GET /api/me`، `POST /api/logout`. نشست فقط به‌صورت هش ذخیره می‌شود، کوئری‌ها parameterized هستند و هر نشست به شرکت خودش محدود است. ورود محدودیت تلاش در جدول MySQL دارد.
- **این بخش نباید به‌جای رابط وب فعلی نشر شود.** سایر APIها عمداً `501` و مسیر رابط `503` پاسخ می‌دهند تا یک API ناقص به اشتباه عملیاتی تلقی نشود.
- نسخه موجود Node/SQLite تا پایان انتقال و آزمون تطابق، دست‌نخورده و مرجع رفتار است. فایل‌های زیر `php/` پایگاه داده Node را نمی‌خوانند؛ هیچ همگام‌سازی واقعی داده هنوز وجود ندارد.

## قرارداد استقرار آینده

1. مسیر پروژه PHP خارج از `public_html` نگهداری شود و **DocumentRoot فقط `php/app`** باشد؛ `php/config.php`، `php/db`، `php/lib`، فایل‌ها و بکاپ‌ها نباید از وب قابل دریافت باشند.
2. `php/config.example.php` را به `php/config.php` منتقل کرده و رمز واقعی MySQL را فقط روی سرور تعیین کنید. فایل واقعی را commit نکنید.
3. در پایگاه داده **جدید و اختصاصی حضوریار** و پس از بکاپ، migrationهای `001` تا `006` پوشه `php/db` به‌ترتیب اجرا شوند. روی دیتابیس خطیار اجرا نشوند. `002` برای اجرای اول طراحی شده و اجرای مکرر `ALTER TABLE` بدون ابزار migration مجاز نیست.
4. ساخت شرکت اولیه فقط با `php php/cli/bootstrap-company.php` و متغیرهای محرمانه محیطی ذکرشده در اسکریپت انجام شود؛ رمز نباید در فرمان یا git ثبت شود. افزونه‌های PHP `pdo_mysql`، `mbstring`، `intl`، `curl` و `zip` نیاز است. رمزهای قدیمی Node با `scrypt` تولید شده‌اند و **بدون فرایند امن بازتنظیم رمز یا ابزار مهاجرت اختصاصی در PHP قابل ورود نیستند**.
5. HTTPS، تنظیم DNS، log محرمانه، محدودیت دسترسی فایل و نسخه پشتیبان MySQL در هاست واقعی تأیید شود.
6. برای اجرای سیاست ۳۰روزه حذف تاریخچه موقعیت حتی در زمان توقف ارسال کارکنان، `php php/cli/prune-location-history.php` را با cron روزانه اجرا کنید. فایل CLI خارج از DocumentRoot بماند.

### شواهد آزمون محلی (۲۰۲۶/۱۱/۰۱)

- PHP CLI 8.3، PDO MySQL، mbstring، intl و curl در محیط موقت توسعه نصب شدند؛ lint فایل‌های PHP موجود بدون خطا بود.
- MariaDB 10.11 محلی با پایگاه **ساختگی** `hozoryar_ci_tmp`: migrationهای 001 تا 006، ساخت دو شرکت، ورود و API کاربران، درخواست استحقاقی با جانشین اجباری، کنترل تداخل و مانده شمسی، جداسازی دو شرکت، replay رویداد تردد، ثبت GPS/موقعیت، نقشه زنده، داشبورد و بایگانی/تأیید مالی آزمایش و موفق شدند.
- هشت سناریوی محاسبه کارکرد و هفت سناریوی پنجره شیفت PHP در `tests/php-work-parity.test.mjs` با `server/work.js` مقایسه شدند؛ هر پانزده مورد برابر بودند. یک آزمون جداگانه نیز ZIP اکسل، RTL، قالب زمان و رنگ بنفش را تأیید کرد.
- این‌ها **آزمون‌های محلی روی داده ساختگی** هستند؛ صحت همه قواعد سازمانی خطیار، کیفیت پاسخ تقویم آنلاین/درگاه واقعی، نمایش خروجی Excel در نرم‌افزار واقعی، HTTP روی هاست خطیار، مهاجرت داده موجود و اپ اندروید روی دستگاه حقیقی هنوز ارزیابی نشده‌اند.

**مانع انتشار:** تا انتقال همه قراردادهای API مورد نیاز پنل و موبایل، فایل‌های استاتیک و تست استقرار روی هاست واقعی کامل نشود، PHP هنوز قابل جایگزینی با نسخه فعلی نیست. موفقیت محلی را نباید موفقیت روی هاست اشتراکی دانست.
