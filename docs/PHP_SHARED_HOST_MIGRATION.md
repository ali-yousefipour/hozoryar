# انتقال حضوریار به هاست اشتراکی خطیار — برنامه و وضعیت

## تصمیم معماری

مسیر فعال PHP خطیار در مرجع موجود `php/app/index.php` + `php/lib/Db.php` + MySQL/MariaDB از طریق PDO است؛ فایل `.htaccess` مسیر `/api` را به روتر PHP هدایت می‌کند. بخش Node موجود در مخزن خطیار نباید به‌عنوان مرجع قطعی اجرای هاست فرض شود. بنابراین **نسخه نهایی هاست اشتراکی حضوریار باید PHP 8.1+ و MySQL/MariaDB باشد** و سرویس دائمی Node یا SQLite را الزام نکند. این انتقال مستقل از پایگاه داده خطیار است.

## وضعیت فعلی این شاخه

- **مرحله ۱ — زیرساخت PHP (آماده برای آزمایش، نه انتشار):** `php/app/index.php`، `php/lib/Db.php`، `php/lib/Auth.php`، فایل آغازین InnoDB، نمونه پیکربندی خارج از DocumentRoot و اسکریپت CLI ساخت شرکت/مالک.
- **مرحله ۲ — زیرمجموعه پرسنل و تردد (پیاده‌سازی اولیه بدون آزمون PHP):** `php/db/002_personnel_attendance.sql` و ماژول‌های `PersonnelApi.php`، `ShiftApi.php`، `AttendanceApi.php`، شامل کاربران، مناطق، تنظیمات شرکت، شیفت‌ها، تخصیص و ورود/خروج GPS با قفل تراکنشی کاربر، شناسه رویداد تکرارپذیر و ثبت ممیزی. اگر تنظیم کنترل پنجره شیفت فعال باشد، ثبت تردد PHP با 501 متوقف می‌شود تا کنترل امنیتی نسخه Node دور زده نشود.
- APIهای احراز هویت: `GET /api/health`، `POST /api/login`، `GET /api/me`، `POST /api/logout`. نشست فقط به‌صورت هش ذخیره می‌شود، کوئری‌ها parameterized هستند و هر نشست به شرکت خودش محدود است. ورود محدودیت تلاش در جدول MySQL دارد.
- **این بخش نباید به‌جای رابط وب فعلی نشر شود.** سایر APIها عمداً `501` و مسیر رابط `503` پاسخ می‌دهند تا یک API ناقص به اشتباه عملیاتی تلقی نشود.
- نسخه موجود Node/SQLite تا پایان انتقال و آزمون تطابق، دست‌نخورده و مرجع رفتار است. فایل‌های زیر `php/` پایگاه داده Node را نمی‌خوانند؛ هیچ همگام‌سازی واقعی داده هنوز وجود ندارد.

## قرارداد استقرار آینده

1. مسیر پروژه PHP خارج از `public_html` نگهداری شود و **DocumentRoot فقط `php/app`** باشد؛ `php/config.php`، `php/db`، `php/lib`، فایل‌ها و بکاپ‌ها نباید از وب قابل دریافت باشند.
2. `php/config.example.php` را به `php/config.php` منتقل کرده و رمز واقعی MySQL را فقط روی سرور تعیین کنید. فایل واقعی را commit نکنید.
3. در پایگاه داده **جدید و اختصاصی حضوریار** و پس از بکاپ، ابتدا `php/db/001_auth_foundation.sql` و سپس `php/db/002_personnel_attendance.sql` اجرا شود. روی دیتابیس خطیار اجرا نشود. `002` برای اجرای اول طراحی شده و اجرای مکرر `ALTER TABLE` بدون ابزار migration مجاز نیست.
4. ساخت شرکت اولیه فقط با `php php/cli/bootstrap-company.php` و متغیرهای محرمانه محیطی ذکرشده در اسکریپت انجام شود؛ رمز نباید در فرمان یا git ثبت شود. `pdo_mysql` و `mbstring` نیاز است. رمزهای قدیمی Node با `scrypt` تولید شده‌اند و **بدون فرایند امن بازتنظیم رمز یا ابزار مهاجرت اختصاصی با `password_verify` در PHP قابل ورود نیستند**.
5. HTTPS، تنظیم DNS، log محرمانه، محدودیت دسترسی فایل و نسخه پشتیبان MySQL در هاست واقعی تأیید شود.

**محدودیت آزمون:** در محیط توسعه فعلی executable `php` وجود ندارد؛ بنابراین syntax و رفتار PDO/MySQL فایل‌های جدید هنوز با PHP واقعی ارزیابی نشده‌اند. موفقیت آزمون‌های Node هیچ‌یک از مسیرهای PHP را اثبات نمی‌کند. مهاجرت تا قبل از راه‌اندازی محیط PHP آزمایشی، تطبیق خروجی و تکمیل همه قراردادهای API قابل انتشار نیست.
