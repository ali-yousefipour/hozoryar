# معماری حضوریار — نسخه پایه 0.1

## چندشرکتی (Multi-tenant)

در نسخه پایه، هر شرکت یک `companies.id` مجزا دارد. `company_id` برای پرسنل، شیفت، تخصیص، ورود و خروج، موقعیت زنده، نشست‌ها، تنظیمات و لاگ عملیات ثبت شده است. کاربر با `company.slug` وارد می‌شود و هویت شرکت از توکن نشست سرور استخراج می‌شود؛ API نباید `company_id` ارسالی کلاینت را مبنای دسترسی قرار دهد.

- مدیر هر شرکت تنها می‌تواند داده همان شرکت را مشاهده کند.
- کلید سرویس پیامک و نقشه نشان برای هر شرکت جدا ذخیره می‌شود و در پاسخ تنظیمات ارسال نمی‌شود.
- ورود و خروج با شناسه کاربر تأییدشده انجام می‌شود؛ ثبت/خواندن تردد سایر کاربران تنها با دسترسی مدیریتی همان شرکت است.
- موقعیت زنده به کارمند شرکت و حضور باز محدود است.
- توکن نشست در پایگاه داده فقط به صورت هش ذخیره می‌شود.
- تنظیمات قابلیت‌ها در سطح شرکت اعمال می‌شود؛ دسترسی‌ها سمت سرور بررسی می‌شوند.
- درخواست‌های مرخصی/مأموریت، تعطیلات دستی و گزارش کارکرد نیز به شرکت و کارمند صاحب داده محدودند.

## محاسبه کارکرد — گام ششم (0.7.0)

در `server/work.js`، نشست‌های حضور برای نمایش تقویمی به روز محلی تهران تقسیم می‌شوند، اما در گزارش **کارکرد** یک نشست عبوری از نیمه‌شب به طور کامل متعلق به تاریخ ورود است تا دو بار شمرده نشود. روز جمعه نسبت به تعطیلی دستی اولویت دارد؛ یک دقیقه حضور نمی‌تواند هم در جمعه‌کاری و هم تعطیل‌کاری گزارش شود. مأموریت و مرخصی تأییدشده به سقف موظفی اعتبار می‌دهند، اما هرگز جزو حضور واقعی محسوب نمی‌شوند. گزارش‌های API تا ۳۵ روز را پوشش می‌دهند.

محاسبه بازه درون شیفت، تأخیر ورود و خروج زودهنگام با ارفاق قابل تنظیم، پنجره‌های مجاز اضافه‌کاری پیش/پس از شیفت و شب‌کاری ۲۲–۶ به موتور واحد اضافه شده‌اند. سقف اضافه‌کاری روزانه و تفکیک مازاد از قواعد مرجع `ShiftCalc.php` الهام گرفته‌اند. `GET /api/calendar` روزهای بازه (جلالی، جمعه و تعطیلات دستی همان شرکت) را برمی‌گرداند و صریحاً `official_calendar_available:false` اعلام می‌کند.

**محدودیت محاسباتی:** موظفی روزانه از شیفت ثابت، هفتگی، شناور یا چرخه کار/استراحت به دست می‌آید؛ ولی سیاست‌های پیچیده ساعات شناور، شیفت‌های چندبخشی، تعطیلات **رسمی** ایران، سیاست‌های منطقه‌ای، تطبیق جامع با نمونه‌های خطیار و نهایی‌سازی ماهانه هنوز تکمیل نشده‌اند. خروجی API با `authoritative:false` نباید برای حقوق و پرداخت قطعی استفاده شود. تاریخ ورودی فرم‌ها فعلاً میلادی است؛ نمایش و ورود جلالی حرفه‌ای در ادامه انجام می‌شود.

**بایگانی ماهانه:** `POST /api/work-months/finalize` فقط با نقش مالک شرکت، برای ماه پایان‌یافته و پس از رفع درخواست‌های معلق و حضور بدون خروج قدیمی مجاز است. گزارش همه کاربران فعال همان شرکت، با همان موتور `buildWorkReport`، در یک تراکنش `BEGIN IMMEDIATE` و با قید یکتایی `(company_id,month)` به‌صورت snapshot ذخیره می‌شود؛ بازنویسی ماه بایگانی‌شده مجاز نیست. `GET /api/work-months` و `GET /api/work-months/YYYY-MM` (یا `j-YYYY-MM`) با دسترسی مدیریتی فقط داده شرکت جاری را نشان می‌دهند. این بایگانی، وضعیت حقوقی یا مالیِ تأییدشده ندارد و داده‌های جدید گزارش زنده آن را تغییر نمی‌دهند.

از نسخه 0.6.0 کلید `j-YYYY-MM` نیز پذیرفته می‌شود؛ بازهٔ واقعی شمسی با `Intl` تقویم فارسی به دست می‌آید. کلیدهای میلادی قدیمی حفظ می‌شوند و مهاجرت جدول بایگانی به‌صورت خودکار و با حفظ snapshot قبلی انجام می‌شود. منبع رسمی برخط همچنان به تأیید نیاز دارد و خروجی غیرمالی است.

از نسخه 0.7.0 داده‌های مرجع تعطیلات ۱۴۰۴ و ۱۴۰۵ خطیار (`php/lib/IranCalendar.php::fallbackEvents`) در `server/official-holidays.js` مستقل از شرکت نگهداری می‌شوند؛ تمام گزارش‌های کارکرد و API تقویم از یک `calendarDays` مشترک استفاده می‌کنند. مرجع رسمی زنده نیست و API همچنان `official_calendar_available:false` برمی‌گرداند، ولی `official_reference_available:true` را برای روزهای پوشش‌داده‌شده اعلام می‌کند. `is_official_holiday`, `is_manual_holiday`, `holiday_source`, `holiday_title` جدا هستند؛ یک روز جمعه حتی اگر در فهرست مرجع باشد، فقط جمعه‌کاری محاسبه می‌شود. سال‌های خارج از مرجع همچنان فقط جمعه و تعطیلی دستی دارند. snapshot جدید این توضیح را ذخیره می‌کند؛ snapshot قدیمی بازنویسی نمی‌شود.

**مدیریت مرکزی:** حساب‌های `platform_admins` و نشست‌های `platform_sessions` از کاربران شرکت‌ها مستقل هستند. مدیر مرکزی با `/api/platform/login` وارد می‌شود و تنها او به فهرست شرکت‌ها و `PATCH /api/platform/companies/:id/subscription` دسترسی دارد. فیلدهای `companies.subscription_end` (آخرین روز معتبر در تهران) و `companies.max_personnel` اختیاری‌اند تا شرکت‌های قدیمی بدون تغییر رفتار ارتقا یابند. ظرفیت، کاربران فعال شامل مدیر را می‌شمارد؛ ایجاد کاربر در تراکنش کنترل می‌شود. پس از انقضا، APIهای GET مجاز می‌مانند اما POST/PATCHهای شرکت خطای 402 می‌دهند، به‌جز خروج از حساب. این قابلیت، درگاه پرداخت یا تمدید خودکار نیست.

در تنظیمات شرکت تعداد مراحل تأیید درخواست ۱ یا ۲ است. در حالت دو مرحله‌ای، مدیر میانی مرحله اول و مدیر شرکت مرحله دوم را تأیید می‌کند. رد درخواست در هر مرحله پایان‌دهنده است. اگر شرکت هیچ مدیر میانی فعال نداشته باشد، مدیر شرکت می‌تواند مرحله نخست را انجام دهد. درخواست‌کننده حق تأیید درخواست خودش را ندارد. تصمیم‌ها برای ممیزی در `request_decisions` ثبت می‌شوند.

### محدودیت‌های نسخه پایه

این نسخه آغاز توسعه است، نه نسخه آماده بهره‌برداری سازمانی. موارد زیر هنوز به فاز بعد نیاز دارند:

- تطبیق کامل موتور کارکرد `ShiftCalc`، داده تعطیلات رسمی، سیاست‌های پیشرفته شیفت، محاسبات حقوق و تأیید مالی ماهانه.
- آزمون واقعی GPS پس‌زمینه و اعلان‌های اندروید، ساخت APK امضاشده و انتشار (کد پایه در `mobile/tracking.js` موجود است).
- صحت‌سنجی تصویری مبتنی بر رضایت و سیاست اعلام‌شده به کاربر؛ از تصویربرداری نامحسوس در این پایه استفاده نشده است.
- تست عملی کلیدهای Neshan و Kavenegar، مدیریت صف، retry و محدودسازی تعداد پیامک.
- SSL/TLS، reverse proxy، بکاپ، rate limiting، مدیریت امن اسرار و سیاست نگهداری داده پیش از انتشار.
- اسکریپت `npm run backup` نسخه پشتیبان SQLite می‌سازد و محدودسازی ورود فعلاً حافظه‌ای/تک‌پردازه است؛ برای استقرار چندسروری باید محدودسازی توزیع‌شده، زمان‌بندی و آزمون بازیابی بکاپ اضافه شود.
- ایزوله‌سازی سخت‌تر در پایگاه داده production از طریق MySQL/PostgreSQL و آزمون‌های نفوذ cross-tenant.

## نقشه و پیامک

نقشه زنده در پنل از OSM یا کاشی‌های Neshan با پراکسی مجازشده استفاده می‌کند. کلید نشان در سمت سرور نگهداری می‌شود. اتصال به Neshan تنها پس از ثبت کلید معتبر در تنظیمات هر شرکت فعال می‌شود. کاوه‌نگار به‌عنوان آداپتور اولیه پیامک پیاده‌سازی شده، اما بدون کلید و روشن بودن قابلیت در شرکت، ارسال ممکن نیست.

## راه‌اندازی توسعه

نیازمند Node.js 22.13 یا جدیدتر است و وابستگی npm خارجی ندارد.

```bash
npm run bootstrap -- acme "شرکت نمونه" admin "replace-with-strong-password" "مدیر سامانه"
npm start
```

سپس `http://127.0.0.1:3000` را باز کنید. برای کار با GPS مرورگر، دامنه امن HTTPS لازم است (localhost استثنا است).

```bash
npm test

# روی سرور، با مسیر مجزا و امن برای نسخه‌های پشتیبان:
npm run backup
```

## منابع قابل استفاده از خطیار

در فازهای بعدی منطق محاسبه کارکرد و تقویم از `php/lib/ShiftCalc.php` و `php/lib/IranCalendar.php`، سیاست‌های حضور از `docs/WEB_PERSONAL_ATTENDANCE.md` و `docs/ATTENDANCE_WORK_CALCULATION.md` و الگوهای نظارت از `docs/internet-work-deduction.md` با بازنویسی مستقل و تست چندشرکتی منتقل می‌شوند. کد خطیار مستقیماً به این پروژه کپی نشده است.
