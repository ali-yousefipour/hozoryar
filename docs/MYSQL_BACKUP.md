# پشتیبان و بازیابی MySQL حضوریار

این ابزار CLI با PHP و PDO/ZipArchive اجرا می‌شود؛ به Node، SQLite یا نصب mysqldump روی هاست نیاز ندارد. افزونه zip باید رمزگذاری AES-256 را پشتیبانی کند. فایل خروجی حاوی داده همه شرکت‌هاست و رمزگذاری آن اجباری است. رمز حداقل ۱۶ نویسه را فقط از محیط امن `HOZORYAR_BACKUP_PASSWORD` می‌خواند.

```sh
php php/cli/database-backup.php create /private/backups/hozoryar-2026-11-02.zip
php php/cli/database-backup.php verify /private/backups/hozoryar-2026-11-02.zip
```

مسیر والد باید موجود و خارج از ریشه وب باشد. مسیرهای public_html هاست را هم برای بکاپ انتخاب نکنید. فایل موجود بازنویسی نمی‌شود. رمز را جدا از فایل بکاپ نگهداری و پس از فرمان از محیط پاک کنید. در زمان ساخت، فایل‌های موقت خصوصی خارج از وب ساخته و پس از پایان حذف می‌شوند؛ پوشه بکاپ باید فقط در دسترس مدیر سرور باشد.

بکاپ شامل snapshot تراکنشی InnoDB، ساختار ستون‌ها و سابقه migrationها، تعداد ردیف و SHA-256 هر جدول است. manifest و داده جدول‌ها با ZIP/AES-256 رمزگذاری می‌شوند. ابزار قبل از اعلام موفقیت، بازخوانی و صحت‌سنجی می‌کند. ورودهای دارای رمز، کلید سرویس شرکت‌ها و نشست‌ها هم بخشی از داده‌اند؛ اشتراک فایل و رمز باید فقط با مسئول بازیابی باشد. ارسال خارج از میزبان و زمان‌بندی بکاپ به تنظیم هاست نیاز دارد.

## بازیابی بدون بازنویسی دیتابیس قبلی

1. دیتابیس **جداگانه و خالی** بسازید و migrationهای همین نسخه را روی آن اجرا کنید.
2. یک config خصوصی جدا برای دیتابیس مقصد بسازید و `HOZORYAR_CONFIG` را به آن اشاره دهید.
3. سرویس وبی که به مقصد متصل می‌شود خاموش باشد؛ دیتابیس قبلی دست‌نخورده می‌ماند.
4. با همان رمز بکاپ اجرا کنید:

```sh
php php/cli/database-backup.php restore /private/backups/hozoryar-2026-11-02.zip --empty-target-confirm
```

ساختار و migration مقصد باید دقیقاً با بکاپ برابر باشد. مقصد دارای هر نوع داده رد می‌شود. INSERTها در یک تراکنش، با ترتیب کلید خارجی و بدون خاموش‌کردن کنترل FK اجرا می‌شوند. ابزار SQL یا DDL داخل بکاپ را اجرا نمی‌کند. شکست، تراکنش را rollback می‌کند. پس از کنترل ورود و شمار داده‌ها، تغییر config سرویس به دیتابیس جدید مرحله جداگانه است.

حد فعلی بررسی بکاپ: مجموع داده غیر‌فشرده حداکثر ۱ گیگابایت و هر ردیف حداکثر ۱۶ مگابایت. برای داده بزرگ‌تر از ابزار پشتیبان MySQL هاست با فرایند بازیابی جدا استفاده کنید.

## شواهد محلی

بکاپ رمزگذاری‌شده دیتابیس محلی شامل ۲۵ جدول و ۱۲ ردیف داده ساخته و بررسی شد؛ در دیتابیس جداگانه `hozoryar_test_restore` بازیابی موفق بود. تلاش دوباره روی مقصد پُر و رمز نادرست رد شد. آزمون خودکار روی دیتابیس آزمایشی نیز رمزگذاری manifest، جلوگیری از بازنویسی، الزام تأیید و رد فایل دستکاری‌شده را بررسی می‌کند.
