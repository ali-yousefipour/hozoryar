# معیارهای آمادگی نسخه سازمانی حضوریار — 0.11.0

> **وضعیت: انتشار سازمانی تأیید نشده است.** این سند آزمون انجام‌شده در مخزن را از کارهای نیازمند زیرساخت، دستگاه و داده واقعی جدا می‌کند. وجود یک API یا گذر تست شبیه‌سازی معادل تأیید عملیاتی نیست.

## ۱. محاسبات خطیار و تأیید مالی

- [x] آزمون خودکار وظیفه شیفت ثابت، هفتگی، چرخشی و چندبازه‌ای، اضافه‌کاری دارای سقف، مازاد، شب‌کاری و عدم دوباره‌شماری جمعه/تعطیل.
- [x] جدا بودن اعتبار مرخصی/مأموریت از حضور واقعی؛ بایگانی تغییرناپذیر، بررسی مدیر و تأیید مالک با ثبت ممیزی.
- [ ] مقایسه خروجی روزانه/ماهانه با **نمونه واقعی ناشناس‌شده** خطیار برای شیفت‌های شناور، خودکار، جمعه/تعطیل هم‌زمان، مناطق، غیبت، کسر اینترنت/GPS، مرخصی، مأموریت و نیروی غیرفعال. اختلاف همه ستون‌ها باید صفر یا مستند و تأییدشده باشد.
- [ ] تعریف سیاست مصوب حقوق (حداکثر ماهانه، جمعه‌کاری در مقابل اضافه‌کار جمعه، مأموریت منهای کسری، گردکردن، مانده انتقالی) برای هر شرکت و امضای مسئول مالی.
- [ ] تا پایان این آزمون‌ها، `authoritative:false` در گزارش‌ها باقی می‌ماند؛ `approved` بایگانی، مجوز پرداخت نیست.

## ۲. نشان و کاوه‌نگار

- [x] آزمون قرارداد HTTP دو درگاه با پاسخ شبیه‌سازی‌شده: کلید نشان فقط در هدر سمت سرور؛ پیامک فقط با دسترسی مالک و قابلیت فعال، کلیدها در تنظیمات GET بازگردانده نمی‌شوند، داده شرکت‌ها جداست.
- [ ] کلید معتبر مجزا برای شرکت آزمایشی در محیط محرمانه وارد شود، نه در Git/issue/تصویر/لاگ. شبکه سرور به `api.neshan.org` و `api.kavenegar.com` متصل باشد.
- [ ] روی محیط staging، یک کاشی نقشه نشان با زوم معتبر و یک پیامک با موافقت صاحب شماره ارسال شود. شناسه/زمان/هزینه/نتیجه شرکت و پاسخ خطا ثبت شود؛ سپس قطع شبکه، کلید نامعتبر، محدودیت اعتبار و نرخ آزمایش شود.
- [ ] مجوز دامنه، سقف هزینه و محدودیت سهمیه هر شرکت در قرارداد سرویس بررسی شود. آزمون ارسال واقعی هزینه‌زا است و بدون کلید انجام نمی‌شود.

## ۳. اندروید و باتری

- [x] مجوز موقعیت foreground/background، اعلان سرویس، ارسال اختیاری در حضور فعال، توقف با خروج و جلوگیری سرور از ارسال بدون حضور در کد وجود دارد.
- [ ] APK امضاشده روی حداقل یک دستگاه Android 8/11/14/16 (یا نسخه‌های موجود با تفاوت رفتار باتری) و تولیدکنندگان متفاوت نصب شود.
- [ ] سنجش ۸ ساعت شیفت با گوشی ساکن/متحرک، اینترنت قطع/وصل، GPS قطع، صفحه خاموش، Doze، بهینه‌سازی باتری فعال/غیرفعال و کشتن فرایند؛ زمان نقاط و اختلاف مسیر با GPS مرجع گزارش شود.
- [ ] مصرف باتری با `adb shell dumpsys batterystats` پیش/پس از بازه و مصرف داده با آمار سیستم ثبت و با اجرای بدون پایش مقایسه شود. **هیچ عدد یا درصدی بدون آزمایش واقعی اعلام نشود.**
- [ ] افشای واضح حریم خصوصی، رضایت کارمند، دوره نگهداری و امکان توقف ثبت نقاط در سیاست شرکت تأیید شود.

## ۴. مرخصی و سیاست اختصاصی

- [x] سقف سالانه استحقاقی (پیش‌فرض ۱۲٬۴۸۰ دقیقه) قابل تغییر برای هر شرکت؛ مانده مبتنی بر سال شمسی و فقط درخواست‌های تأییدشده؛ رد شدن تأیید نهایی بیش از سهمیه در تراکنش امن.
- [x] آزمون مرز نوروز، جداسازی شرکت‌ها، تأیید دومرحله‌ای و درخواست چندروزه.
- [ ] انواع تکمیلی (بدون حقوق، زایمان، ازدواج/فوت، مرخصی استعلاجی مشروط)، ذخیره مانده انتقالی، سیاست جایگزین بر اساس منطقه و تبصره‌های هر شرکت با تأیید منابع انسانی طراحی/آزمون شوند.
- [ ] سیاست کسر سهمیه برای تعطیلات میانی، نیم‌روز و کارکنان پاره‌وقت مشخص شود. در 0.11.0 `minutes` هر روزِ درخواست روزانه، حتی تعطیل، از سهمیه کسر می‌شود؛ این سیاست نیازمند تصمیم شرکت است.

## ۵. امنیت، بازیابی و استقرار

- [x] تست جداسازی tenant، احراز هویت و نقش، محدودیت تأیید خود، مخفی‌بودن کلیدها؛ بررسی SQLite با `integrity_check` و `foreign_key_check`؛ آزمون بازیابی آفلاین و حفظ فایل قدیمی.
- [ ] بازبینی امنیت مستقل (OWASP ASVS)، بررسی وابستگی‌ها، نشست‌ها، rate-limit چندنمونه‌ای، محدودیت درخواست‌های پیامک/کاشی، لاگ ممیزی و امنیت کلیدها و TLS.
- [ ] روی سرور آزمایشی با داده مصنوعی: پشتیبان کامل، بررسی صحت، توقف سرویس، بازیابی آفلاین، راه‌اندازی مجدد، مقایسه شمارش داده‌ها/مرخصی/بایگانی، سنجش RPO و RTO، تمرین rollback.
- [ ] تست بار هم‌زمان برای چند شرکت، کیفیت ثبت ورود در قطع اتصال، مانیتور خطا/فضای دیسک/کش تعطیلات، بکاپ زمان‌بندی‌شده رمزگذاری‌شده خارج از میزبان، هشدار و آزمون چرخش کلید.

## دستورات محلی تأییدپذیر

```bash
npm test
npm run backup
npm run verify-backup -- /absolute/path/backup.sqlite
# restore فقط پس از توقف سرور و روی محیط آزمایشی:
DB_PATH=/absolute/path/staging.sqlite npm run restore-backup -- /absolute/path/backup.sqlite --offline-confirm
```

تا پایان موارد بدون تیک، **Go-Live = NO-GO**. این محدودیت به معنی نقص تست‌های واحد نیست؛ به معنی نبود شواهد موردنیاز برای تضمین سازمانی است.
