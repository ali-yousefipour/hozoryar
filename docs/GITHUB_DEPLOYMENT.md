# استقرار حضوریار با GitHub Actions

اکشن `.github/workflows/deploy-hozoryar.yml` روی push شاخه main اجرا می‌شود؛ شاخه توسعه و PR فقط اعتبارسنجی و ساخت بسته را انجام می‌دهند. اجرای دستی روی main با ورودی upload نیز ممکن است.

## مقصد و حساب

- سرور: `2450773184.cloudylink.com`، پورت ۲۱؛ ریشه عمومی تأییدشده توسط کاربر: `public_html` در حساب FTP.
- نام سکرت‌ها در YAML: `ftp` و `pass`. GitHub آن‌ها را در فهرست به صورت `FTP` و `PASS` نمایش می‌دهد و نام‌ها حساس به بزرگی حروف نیستند. هیچ مقداری در مخزن ذخیره نمی‌شود.
- گواهی خودامضاشده هاست با نام `s387.bitcommand.com` در `deploy/cloudylink-ftps.pem` پین شده است؛ SHA-256 مشاهده‌شده هنگام راه‌اندازی: `6f0562d9aa960b8d1f14bede60985f93e5497ab03704bd5e4612b34bbf04bbb7`.
- گواهی از اتصال بدون ورود همین سرور دریافت شد؛ تأیید مستقل اپراتور میزبان انجام نشده است. پیش از ورود، زنجیره/تاریخ و اثرانگشت دقیق بررسی می‌شوند. اعتبارسنجی نام مستعار Cloudylink با تطبیق دقیق گواهی جایگزین شده است؛ خاموش‌کردن عمومی TLS یا انتقال رمز به صورت FTP ساده وجود ندارد. تعویض گواهی میزبان نیازمند بررسی و به‌روزرسانی همین فایل عمومی است.

## ترتیب اجرا

۱. PHP 8.3، Node 24 و MariaDB 11.4 برای تست ایزوله راه‌اندازی می‌شوند. یازده migration، lint، آزمون‌های Node/PHP/MySQL و آزمون‌های اسکریپت استقرار باید موفق شوند. دیتابیس CI مستقل است.
۲. بسته نصب ساخته و به عنوان artifact همان commit نگهداری می‌شود؛ deploy همان artifact را دریافت می‌کند.
۳. برنامه در `hozoryar/releases/<commit>/` خارج از public_html بارگذاری و همه فایل‌ها با دانلود مجدد و SHA-256 کنترل می‌شوند. پوشه releases عمومی نیست.
۴. ورودی و htaccess قبلی در `hozoryar/rollback/<run-id>/` نگهداری می‌شوند. پس از تکمیل نسخه، index.php با rename جایگزین می‌شود؛ فایل نسخه عمومی آخرین مرحله است. انتقال کل حساب و دیتابیس اتمیک نیست، ولی فعال‌شدن کد برنامه از طریق یک ورودی انجام می‌شود.
۵. فایل‌های قدیمی، config واقعی و دیتابیس حذف نمی‌شوند. اجرای هم‌زمان استقرار متوقف نمی‌شود تا انتقال نیمه‌کاره رها نشود.

## تنظیم دیتابیس و بازگشت

پیکربندی ثابت باید در `hozoryar/php/config.php` خارج از public_html باشد. ورودی منتشرشده `HOZORYAR_CONFIG` را به همین مسیر اشاره می‌دهد؛ اکشن این فایل را نمی‌سازد و بازنویسی نمی‌کند. برای نصب اول، نمونه config داخل پوشه نسخه را با اطلاعات واقعی دیتابیس در مسیر ثابت قرار دهید. migration یا ساخت مدیر روی دیتابیس واقعی در این اکشن اجرا نمی‌شود.

در Terminal هاست برای کارهای CLI، `HOZORYAR_CONFIG` را به مسیر مطلق config ثابت تنظیم کنید و ابزار نسخه فعال را اجرا کنید؛ برای مثال `php /home/ACCOUNT/hozoryar/releases/COMMIT/php/cli/check-environment.php`. راهنمای نصب و بکاپ در SHARED_HOST_SETUP.md و MYSQL_BACKUP.md است.

برای rollback، index.php و htaccess ذخیره‌شده را در public_html بازگردانید؛ نسخه‌های قبلی حفظ می‌شوند. بازگردانی فایل ورودی، مهاجرت یا تغییر داده را معکوس نمی‌کند. موفقیت FTP به معنای آماده بودن دیتابیس، HTTPS دامنه عمومی یا تست کامل ورود کاربران نیست.

این طرح از جلوگیری از تداخل و کنترل فایل‌های خطیار، جداسازی داده و مقصد صدوریار، و آماده‌سازی نسخه و بررسی checksum سرویس‌یار استفاده می‌کند. کد، تنظیمات و استثناهای ضعیف TLS آن سامانه‌ها کپی نشده‌اند.
