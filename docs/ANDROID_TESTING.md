# بررسی اپ اندروید با Codex

امکان اجرای APK و بررسی رابط، مجوزها و logcat از طریق دستگاه اندرویدی یا شبیه‌ساز وجود دارد. مرورگر داخلی خود یک Android Runtime نیست. اسکیل فقط روش کار و اسکریپت‌های آن را تعریف می‌کند؛ شبیه‌ساز یا گوشی باید جداگانه موجود باشد.

دو مسیر:

1. **محلی:** Android Emulator/AVD یا گوشی توسعه متصل، Android SDK Platform Tools و فایل APK توسعه. اجرا و نصب با ابزارهای Android و بازرسی از طریق ابزار دستگاه یا MCP مورد اعتماد انجام می‌شود. برای گوشی واقعی، تأیید دسترسی debugging روی خود گوشی لازم است.
2. **MCP دستگاه:** یک سرور MCP قابل بررسی می‌تواند نصب APK، مشاهده صفحه، لمس، خواندن UI و logcat را به ابزارهای Codex اضافه کند. دسترسی را به دستگاه آزمایشی مشخص محدود کنید. اتصال MCP و داشتن اسکیل راهنما دو بخش مکمل هستند؛ اسکیل به تنهایی جای ابزار اجرایی را نمی‌گیرد. یک سرویس ابری نیز ممکن است هزینه، حساب کاربری و ارسال APK بخواهد؛ در این تغییرات سرویس خارجی متصل یا نصب نشده است.

## وضعیت این سیستم

پوشه SDK در `C:\Users\Administrator\AppData\Local\Android\Sdk` و `platform-tools/adb.exe` موجود است. پوشه emulator فقط اطلاعات نصب داشت و `emulator.exe` در آن نبود؛ اجرای آماده شبیه‌ساز/AVD تأیید نشد. فرمان فهرست دستگاه نیز در محیط محدود فعلی به خطای دسترسی پوشه تنظیمات Android رسید؛ وجود یا نبود گوشی متصل تأیید نشده است. در جست‌وجوی فهرست افزونه‌های در دسترس، افزونه مرتبط آماده‌ای پیدا نشد؛ فهرست جامع نیست.

## اتصال به بک‌اند حضوریار

- بک‌اند PHP محلی اکنون `http://127.0.0.1:3001` است.
- روی دستگاه توسعه تأییدشده، می‌توان `adb -s SERIAL reverse tcp:3001 tcp:3001` را استفاده کرد و API اپ را به localhost همان پورت متصل کرد. در Emulator نیز میزبان معمولاً از `10.0.2.2` قابل دسترسی است.
- نشانی API در `mobile/app.json` تنظیم می‌شود. HTTP فقط برای ساخت توسعه با تنظیم مناسب شبکه است؛ نسخه انتشار باید HTTPS واقعی داشته باشد.
- سناریوهای آزمون: ورود شرکت، ثبت تردد با GPS، replay شناسه رویداد، خروج صریح، رد ثبت خارج از محدوده، صف آفلاین، مجوزها و ارسال موقعیت فقط در حضور فعال. قابلیت GPS پس‌زمینه باید با Development Build/APK و دستگاه واقعی هم ارزیابی شود.
