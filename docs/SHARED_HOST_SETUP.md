# نصب حضوریار روی هاست لینوکسی اشتراکی

مسیر اصلی اجرا PHP 8.3 و MySQL/MariaDB است. Node تنها مرجع آزمون محاسبات و پروژه اندروید است و روی هاست نصب نمی‌شود.

## چیدمان فایل‌ها

با `php php/cli/package-shared-host.php` بسته `data/hozoryar-shared-host.zip` را بسازید. بسته شامل رمزها، دیتابیس محلی، Node و فایل‌های توسعه نیست.

بسته را در پوشه خانه حساب هاست باز کنید، به‌گونه‌ای که `public_html` و `hozoryar` هم‌سطح باشند. فقط محتوای `public_html` قابل دسترسی وب است. اگر دامنه DocumentRoot اختصاصی دارد، می‌توانید آن را مستقیماً روی `hozoryar/php/app` تنظیم کنید. دامنه باید از ریشه سرو شود؛ نصب در زیرپوشه فعلاً پشتیبانی نمی‌شود.

## تنظیم و ایجاد دیتابیس

1. PHP 8.3+ با pdo_mysql، mbstring، intl، curl و zip و Apache با mod_rewrite فعال کنید.
2. یک دیتابیس اختصاصی UTF-8 حضوریار و کاربر مجاز آن بسازید.
3. `hozoryar/php/config.example.php` را به `config.php` کپی کنید و اطلاعات همان دیتابیس را تنظیم کنید. فایل خارج از public_html بماند و در Git ثبت نشود.
4. از پوشه `hozoryar` دستور `php php/cli/migrate.php` را اجرا کنید. برای نصب موجود با migration دستی ابتدا تطبیق schema لازم است؛ ابزار روی دیتابیس بدون سابقه و دارای جدول companies متوقف می‌شود. شکست DDL نیازمند بررسی است و خودکار تکرار نمی‌شود.
5. متغیرهای HOZORYAR_COMPANY_SLUG، HOZORYAR_COMPANY_NAME، HOZORYAR_OWNER_USERNAME، HOZORYAR_OWNER_NAME و HOZORYAR_OWNER_PASSWORD را در محیط امن تنظیم و `php php/cli/bootstrap-company.php` را اجرا کنید. رمز حداقل ۱۲ نویسه و خارج از history فرمان باشد. سپس متغیر رمز را پاک کنید.
6. HTTPS دامنه را فعال کنید. از `/api/health` پاسخ `service: hozoryar-php` بگیرید و ورود و جداسازی دو شرکت را بررسی کنید.
   اتصال HTTPS خروجی PHP به تقویم رسمی هم باید با CA معتبر کار کند. در صورت خطای issuer، بسته گواهی هاست یا تنظیم curl.cainfo را اصلاح کنید؛ اعتبارسنجی TLS نباید خاموش شود.
7. cron روزانه `php /home/ACCOUNT/hozoryar/php/cli/prune-location-history.php`، پشتیبان MySQL و بازگردانی آزمایشی را تنظیم کنید.

هاست بدون SSH: فایل یکپارچه `php/db/migrations/hozoryar-install.sql` را فقط یک‌بار با phpMyAdmin روی دیتابیس جدید و خالی وارد کنید؛ این فایل تمام migrationهای 001 تا 011 و سابقه آن‌ها را دارد. فایل‌های شماره‌دار را همراه آن دوباره ایمپورت نکنید. راهنمای اتصال و مسیر دقیق config در `php/db/migrations/README.md` آمده است. ساخت مدیر را از Terminal کنترل‌پنل یا پشتیبانی هاست انجام دهید؛ فایل نصب عمومی برای ساخت مدیر وجود ندارد.

## توسعه محلی

پس از تنظیم MySQL و `php/config.php`، از ریشه پروژه:

```sh
php php/cli/migrate.php
php -S 127.0.0.1:3000 -t php/app php/app/index.php
```

سرور داخلی PHP مخصوص توسعه است؛ روی هاست Apache/PHP استفاده می‌شود. حساب‌های SQLite قبلی خودکار به MySQL منتقل نمی‌شوند. مرزهای انتقال APIها و آزمون‌های عملیاتی در PHP_SHARED_HOST_MIGRATION.md ثبت شده‌اند؛ بسته‌بندی به معنای تأیید انتشار همه قابلیت‌ها نیست.
## دستگاه حضور و غیاب

مدیر شرکت در «محل‌های کار ← دستگاه حضور و غیاب» دستگاه را به یک محل کار اختصاص می‌دهد. بعد از ثبت، پنل نشانی اتصال و کلید را یک‌بار نمایش می‌دهد. رابط مورد اعتماد دستگاه باید درخواست JSON را به این نشانی روی HTTPS بفرستد و کلید را در سرآیند `Authorization: Bearer <key>` قرار دهد. IP و پورت ثبت‌شده برای شناسایی دستگاه هستند. رابط دستگاه روی شبکهٔ محل کار، دادهٔ دستگاه را به درخواست HTTPS تبدیل می‌کند.

برای بررسی ارتباط، رابط با `POST` بدنهٔ `{"action":"ping"}` را می‌فرستد. پاسخ ۲۰۰ یعنی کلید معتبر است. در پنل، «به‌روزرسانی وضعیت اتصال» زمان آخرین ارتباط را نشان می‌دهد. برای تردد، رابط هنگام دریافت رویداد بدنه‌ای مانند `{"action":"in","username":"employee01","event_id":"terminal-event-714"}` می‌فرستد. مقدار `action` برای خروج `out` است. نام کاربری باید به کارمند فعال در همان محل کار تعلق داشته باشد. شناسهٔ رویداد باید ثابت، یکتا برای همان دستگاه و کارمند، و شامل ۱ تا ۶۴ حرف لاتین، عدد، خط تیره یا زیرخط باشد. ارسال دوبارهٔ همان رویداد با پاسخ ۲۰۰ تأیید می‌شود. رویداد تازه با پاسخ ۲۰۱ ثبت می‌شود و از ساعت سرور استفاده می‌کند. این مسیر برای ثبت زنده است. رویدادهای بایگانی‌شده باید از مسیر اصلاح تردد ثبت شوند.

این مسیر به رابط HTTPS نیاز دارد. پروتکل اختصاصی سازنده و اتصال مستقیم به پورت دستگاه در این بسته پیاده‌سازی نشده‌اند. هر کلید فقط به یک دستگاه و محل کار تعلق دارد. مدیر می‌تواند کلید را عوض کند یا دستگاه را غیرفعال کند.

## مسیرهای وب پس از بازطراحی

صفحه عمومی `/` و ورود `/login` است؛ `/index.html` هم برای سازگاری باقی می‌ماند. میانبر نصب‌شده وب از `/login` شروع می‌شود. لوگوی PNG موجود دارای خطای decode است؛ پیش از انتشار آیکن نصب و splash اندروید، نسخه سالم همان لوگوی تأییدشده را جایگزین کنید. جزئیات آزمون محلی و حدود انتشار در REDESIGN_EXECUTION.md آمده است.
